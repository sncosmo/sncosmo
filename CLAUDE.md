# sncosmo: notes for Claude Code

## Releases
- Run `/release` (or `/release --dry-run`). It follows the release procedure
  in `docs/contributing.rst` with an approval checkpoint before every change.
  See `.claude/skills/release/`.
- The version bump (`Prepare for vX.Y.Z`) is pushed directly to `master`;
  CI runs on that push before the GitHub release is created.
- Publishing a GitHub release triggers the PyPI upload. Never run
  `gh release create` without explicit maintainer approval.

## Repo conventions
- Design notes and specs live next to the tooling they describe (e.g.
  `.claude/skills/release/DESIGN.md`), never in `docs/`. `docs/` is the
  Sphinx source for ReadTheDocs user documentation.
- Docstrings are numpy-style.
- Changelog entries go in `docs/history.rst` as `- Description (#PR)`.

## Building and packaging
- `python -m build` from the repo root fails: the local `build/` directory
  shadows the `build` package. Use `uvx --from build pyproject-build` (run
  from outside the repo, or pass the repo path).
- Wheels contain only `sncosmo` and `sncosmo.tests`; the sdist contents are
  set by `MANIFEST.in`. `.claude/`, `docs/`, and this file are not packaged.
- `docs/sg_execution_times.rst` is generated by the docs build; don't commit it.

## Known CI flakiness
- **Download all of the builtins**: fails intermittently with HTTP 503 from
  `sncosmo.github.io` (GitHub Pages). Not caused by code changes; re-run.
- **Python 3.11 with oldest supported version of all dependencies**:
  `test_spectrum.py::TestSpectrum::test_bandfluxcov` fails intermittently
  with an asymmetric covariance from `Spectrum.rebin`. Suspected cause:
  numpy 1.23.2 bundles OpenBLAS 0.3.20, which has a known wrong-results bug
  on some newer CPUs, so it depends on which runner hardware the job lands on.
  Unconfirmed: the runner CPU model is not logged.
